# 交接说明 · 把工具交给他人试用

> 本文档面向**发工具的人**（你）。对方只需要看 `README.md` 的「方案 A：图形界面」一节，
> 或者干脆什么都不看 —— 双击 `start.bat` 就行。

---

## 一、发什么，不发什么

### ✅ 要发的

```text
smartedu-autowatch/
├── start.bat                 ← 对方双击这个
├── package.json
├── LICENSE
├── README.md
├── src/                      全部
├── userscript/               全部
├── tools/                    全部（可选，但不占多少体积）
└── docs/                     全部
```

### ❌ 绝对不要发的

| 路径 | 为什么 |
| --- | --- |
| `out/` | 运行日志与探测结果。`out/*-recon.json`、`out/run-*.log` 会**原样记录平台返回的个人 userId 与登录 token** |
| `node_modules/` | 体积大、平台相关，对方 `start.bat` 会自己装 |
| `.chrome-profile/` | 独立 Chrome profile，**里面有登录 cookie**，等于你的账号 |
| `%LOCALAPPDATA%\smartedu-auto-profile\` | 同上（挂课用的 profile 在这个目录） |
| `%LOCALAPPDATA%\smartedu-autowatch-ui\` | 界面窗口的 profile |
| `*.lock` | 进程锁，含本机 PID，无意义 |

### 打包命令（安全的那种）

不要用「右键 → 压缩整个文件夹」。用白名单复制，再用自带的自检脚本扫一遍：

```bash
# 1) 白名单复制到一个干净目录（绝对不要 cp 整个目录）
mkdir -p /tmp/handoff/smartedu-autowatch
cd /e/wpg/project/coding/pi/smartedu-autowatch
for i in start.bat package.json LICENSE README.md src userscript tools docs; do
  cp -r "$i" /tmp/handoff/smartedu-autowatch/
done

# 2) 扫凭据（模式不写在这里 —— 写在这里的话文档会命中自己，详下）
node tools/check-handoff.mjs /tmp/handoff/smartedu-autowatch
```

输出「✅ 可以发包」才发。

> **发出去之前，务必跑一次 `node tools/check-handoff.mjs`。**
> 它会把个人凭据扫出来，并列出「存在但不该随包发出」的目录；
> 全部通过才发。
>
> 顺带说明为何不把所有搜索模式写在文档里：文档本身要随包分发，写进去就会
> 命中自己，自检就永远是「有发现」—— 最后逼得人把警告当噪音忽略。
> 所以模式集中在脚本里，脚本排除自身。

## 二、对方要做的（只有三步）

1. **装 Node.js**（只需一次）
   打开 <https://nodejs.org/zh-cn/download>，下载 **LTS** 版本，一路「下一步」。
   装完**关掉所有命令行窗口**再继续。

2. **解压到一个不带中文、不带空格的路径**
   推荐 `D:\smartedu-autowatch\`。
   （放在桌面或「下载」里也能用，但如果 Windows 用户名是中文，偶尔会有怪问题。）

3. **双击 `start.bat`**
   - 首次会自动装依赖，十几秒，窗口里会滚动一堆字，正常。
   - 然后弹出一个没有地址栏的窗口，就是界面。

### 首次使用：先登录

界面上点 **「先登录（只需一次）」**，会弹出一个真实的 Chrome 窗口。
在**那个窗口里**登录平台（扫码或账号密码），登录成功后程序会自己继续。
这个登录态会一直留着，以后不用再登。

## 三、试用验收清单

让对方按顺序走一遍，每步确认「看到的现象」和预期一致。
有任何一步对不上，都值得记下来反馈。

### 启动阶段

- [ ] 双击 `start.bat` 后，**没有**一闪而过的黑窗口直接消失
      （如果闪退，多半是没装 Node.js，或 `node_modules` 装失败）
- [ ] 窗口标题是「教师研修 · 自动挂课」
- [ ] 界面上**没有任何输入网址的地方**（这是设计，不是缺失）
- [ ] 「选择专题」下拉框里**能列出专题**，并且显示「11 门课 / 目标 10 学时 / 截止 2026-09-30」这类信息
      → 这一步走通了，说明**免登录拉列表**是好的
- [ ] 「选择要挂的课程」里默认**全部勾选**，右侧显示「已选 11 / 11 门 · 合计 199.38 学时」

### 登录阶段

- [ ] 点「先登录（只需一次）」后，弹出了一个**真实的 Chrome 窗口**（不是界面窗口）
- [ ] 在弹出窗口里登录后，**不需要点任何按钮**，程序自己往下走
- [ ] 界面日志区开始滚动文字

### 挂课阶段

- [ ] 点「开始挂课」后，日志区出现「起跑基线：已学习 X 学时｜已认定 Y/10 学时」
- [ ] 日志里每秒滚动一行进度，包含：课程名、`00:12/1420s`、`倍速=2`、`▶播放`、`平台=X学时`
- [ ] **平台学时数字会跳**（不会一直停在 0）—— 这是判断「平台有没有在记账」的关键
- [ ] 视频**没有声音**（静音是故意的，见 README「千万不要把视频静音」一节说明的反面）

### 关键验证：真的会记账吗

这是最容易出错、也最值得确认的一点：

- [ ] 观察 **15 分钟以上**，确认「平台」那个数字**从 0 变成了非 0**
      （平台按整节视频记账，一节播完才会计入，所以需要等）
- [ ] 若有条件，登录平台网页版看「已学习学时」，与界面里的数字**大体对得上**

### 收工与中断

- [ ] 关掉界面窗口后，**挂课仍在继续**（进程没死）
- [ ] 再双击一次 `start.bat`，窗口回来，日志**接着显示之前的进度**（接回同一个任务）
- [ ] 点「停止」，日志出现「⏹ 已停止」，进程真的退出

### 异常场景（值得主动测一下）

- [ ] 在挂课进行中，**再双击一次 `start.bat`**
      → 预期：**不崩溃**，只是把窗口再打开/切到前面
      （旧版本这里会 `exitCode=21` 崩，现在应该给人话提示）
- [ ] 挂课进行中，手动把浏览器窗口点掉/最小化
      → 预期：挂课不受影响

## 四、让对方反馈什么

直接把这个模板发给对方，让他填空：

```text
【能不能用】能用 / 不能用

【卡在哪一步】启动 / 登录 / 开始挂课 / 挂课中途 / 收工

【看到的现象】
（照抄界面上的文字，或截图）

【有没有报错】
（日志区最后 10 行，或截图）

【系统】Windows 几？用户名是中文吗？
```

**最需要反馈的信息**：界面上「平台=X学时」这个数字**有没有动过**。
这个是判断整个工具是否真正生效的唯一硬指标。

## 五、常见问题

| 现象 | 原因 | 怎么办 |
| --- | --- | --- |
| 双击 `start.bat` 闪一下就没了 | 没装 Node.js，或装完没重开窗口 | 装 Node.js LTS，重开窗口再双击 |
| 窗口里说「缺少 Node.js」并打开了浏览器 | 预期行为，引导装 Node.js | 装完关掉窗口重来 |
| 说「找不到 Chrome」 | 没装 Chrome，或装在非标准路径 | 装官方 Chrome：<https://www.google.cn/chrome/> |
| 说「浏览器正被另一个进程占用」 | 已经有一个挂课在跑 | 先「停止」，或复用已经开着的那个窗口 |
| 界面是白的 / 一片空白 | 界面服务没起来 | 关掉窗口重开；或看 `out/ui-launch.log` |
| 卡在「正在准备依赖」很久 | npm 网络问题 | 换国内源：`npm config set registry https://registry.npmmirror.com` |
| 登录窗口里登录了，但程序没反应 | 登录态判定没抓到 | 等十几秒；还不行就在那个窗口里刷新一次页面 |
| 「平台」数字一直是 0 超过半小时 | 平台没在记账，是真问题 | **这是最值得反馈的情况**，把日志发回来 |

## 六、发之前自查（你来做）

- [ ] `node tools/check-handoff.mjs` 报告源码无凭据，且已排除 `out/`、`node_modules/`
- [ ] `out/` 没有被打进压缩包
- [ ] 没有把 `.chrome-profile/` 或 `%LOCALAPPDATA%` 下的 profile 打进包
- [ ] `start.bat` 在**一个干净的、没装过 node_modules 的目录**里试过一次
      （这一步能验出「首次运行」路径，是最容易坏的路径）
- [ ] `README.md` 的方案 A 一节对方能看懂（找个没接触过的人读一遍最快）
